# WeKan ↔ Home Assistant Integration

> *Generated by [aurora@aurora-smart-home (home-assistant skill)](https://github.com/tonylofgren/aurora-smart-home)*

All WeKan automation lives in **`packages/package_wekan.yaml`** — rest_commands,
automations, and scripts together in one file for AI context isolation. Nothing
WeKan-related belongs in `configuration.yaml`, `automations.yaml`, or
`scripts.yaml` anymore (they were extracted 2026-09-07).

## Architecture

- HA `rest_command` → WeKan REST API at `https://wekan.spencerslab.com`.
- Auth: `Authorization: !secret wekan_api_token`. The secret stores the **full
  header value including the `Bearer ` prefix**. Long-lived token; see gotchas.
- Live board inspection during development: the **wekan MCP tools**
  (`global-admin-wekan_*` / `global-readonly-wekan_*`) — prefer these over
  adding throwaway REST plumbing just to look at the board.

## Nightly flow

`automation.boards_daily_task_organization` at **00:01 America/Denver**
(= 06:01 UTC) runs, in order:

1. `boards_update_recurring_tasks` — bump recurring due dates (Today / Inbox-Reset)
2. `boards_archive_past_unlabeled_tasks` — archive past-due unlabeled cards
3. `boards_reset_inbox_cards` — archive past-due "Events & Waiting" cards;
   uncheck all checked checklist items on cards labeled "Reset Checklists"
4. `boards_move_future_cards_to_default` — future-dated cards Today → Default
5. `boards_organize_by_labels` — label→list moves in the Default swimlane
6–9. `boards_next_week_s_tasks` ×4 — cascade Default → Next Week →
   This Week & Weekend → Tomorrow → Today by due-date window

Cascade windows are **calendar-day** comparisons, run-time independent:
a card moves when `as_local(as_datetime(dueAt)).date() < (now() + timedelta(days=timeDelta)).date()`
(same for `startAt`). With timeDeltas **14 / 7 / 2 / 1** the resting buckets
are: Today = due today or overdue · Tomorrow = due tomorrow · This Week &
Weekend = due 2–7 days out · Next Week = due 7–14 days out · Default = beyond
14 days or undated. `boards_move_future_cards_to_default` uses the matching
calendar-day check (`due-date > today`) so cards due later *today* are never
shuttled to Default and back. (Before 2026-09-07 the cascade subtracted a
day from card dates as stale timezone compensation — that over-included by a
full day, landing tomorrow-due cards in Today, and midday manual runs made it
worse.)

Order matters: recurring bumps run **before** the reset step so a card with
both a recurring label and Events & Waiting gets renewed instead of archived;
the reset runs **before** future-card moves so checklists are refreshed before
a card leaves the swimlane. Every step has `continue_on_error: true` — one
failing step (e.g. expired token) must never abort the rest of the chain.

## rest_command inventory (in the package)

| Command | Method | Purpose |
|---|---|---|
| `get_board` | GET | Board document incl. `labels` |
| `get_board_lists` | GET | Board lists `{_id, title}` |
| `get_board_swimlanes` | GET | Swimlanes `{_id, title}` |
| `get_cards_from_swimlane` | GET | All cards in one swimlane |
| `get_card` | GET | Full card document (incl. `labelIds`, `dueAt`) |
| `get_card_checklists` | GET | Card's checklists — **without items** |
| `get_checklist` | GET | One checklist — **with items array** |
| `update_card_due_date` | PUT | Set `dueAt` |
| `move_card_to_swimlane` | PUT | Move card (listId + swimlaneId) |
| `archive_card` | PUT | `{"archive": "true"}` — recoverable |
| `update_checklist_item` | PUT | `{"isFinished": bool}` per item |
| `add_board_label` | PUT | Add a label `{name, color}` to the board |

Hard-delete was deliberately removed (archive is recoverable; the wekan MCP
server also omits destructive ops by design).

## The `boards_reset_inbox_cards` contract

Fields: `boardId`, `swimlane_name` (Today), `list_name` (Inbox/Reset),
`event_label_name` (Events & Waiting), `reset_label_name` (Reset Checklists).
Per card in `<swimlane_name>`:

- list ≠ `<list_name>` → skip
- has `<event_label_name>` label **and** `dueAt < now` → **archive**
- no event label **and** has `<reset_label_name>` label → fetch each
  checklist, uncheck every checked item
- otherwise → skip

## How to extend

1. **New REST operation**: add a `rest_command` to the package. Endpoint
   reference: `/home/coder/SpencersLab/skills/wekan-api/references/rest-api-overview.md`.
2. **New script**: follow the package's fetch → guard → loop pattern
   (see `boards_reset_inbox_cards`): resolve swimlane/list by name, fail fast
   with a diagnostic when the first fetch returns a non-list, guard every
   `for_each` against non-list payloads.
3. **Wire into the nightly chain**: add the action to
   `Boards: Daily Task Organization` with `continue_on_error: true` and pass
   **every field explicitly** (gotcha #5).
4. **Test loop**: run the script with a fake `list_name` (e.g. `___probe___`)
   for a safe no-op pass → inspect with `homeassistant_manage_trace` →
   real run → verify board state via the wekan MCP tools.

## Gotchas (learned the hard way, 2026-09-07)

1. **Jinja dict-method name collision.** On a dict, `x.items` resolves to the
   built-in `dict.items` method — Jinja tries attribute access *before*
   subscript. Any WeKan field named like a dict method (`items`, `keys`,
   `values`, `get`, `update`, `pop`, `copy`) **must** use subscript access:
   `content['items']`. This crashed the reset script twice
   (`repeat.item.items`, then `checklist_detail.content.items`) with
   `TypeError: 'builtin_function_or_method' object is not iterable`.
2. **WeKan list endpoints return reduced documents.**
   `GET /cards/:id/checklists` omits each checklist's `items` (fetch each
   checklist via `get_checklist`); the list-cards endpoint omits `labelIds`
   (fetch each card via `get_card`).
3. **Errors arrive as payloads.** rest_command does not raise on 4xx — the
   Meteor error object lands in `response_variable.content`. Guard the first
   fetch and fail fast:
   `{% set c = (resp | default({})).content %}{{ not (c is defined and c is iterable and c is not string and c is not mapping) }}`,
   and wrap every `for_each` with
   `{{ x if x is sequence and x is not string else [] }}`.
4. **Tokens expire.** Default lifetime 90 days
   (`ACCOUNTS_COMMON_LOGIN_EXPIRATION_IN_DAYS`); re-login does not invalidate
   old tokens; server needs `WITH_API=true`. Failure signature: everything
   works, then every call returns 401 from one moment to the next. Fix =
   fresh token from `POST /users/login` into `secrets.yaml` + HA restart.
5. **Script field `default:` values do not apply to programmatic service
   calls** — pass every field explicitly (the nightly automation does). UI
   runs apply defaults.
6. **HA Jinja `is sequence` returns True for Undefined.** Use the
   `is defined and is iterable and is not string and is not mapping`
   formulation instead.
7. **`system_log.write` at info/debug never shows in the system-log ring
   buffer** (WARNING+ only). Use traces (`homeassistant_manage_trace`) to
   verify which branch ran.
8. **Packages load at startup** — restart HA after changing the package.
   `rest_command:`, `automation:`, `script:` all merge from packages;
   `!secret` works inside them.
9. **Moving YAML automations/scripts between files**: keep `alias:` / script
   keys byte-identical so entity IDs survive; disabled state of YAML
   automations lives in the entity registry, keyed by entity_id.
10. **Date cutoffs are calendar-day, not rolling-24h.** Compare
    `as_local(as_datetime(x)).date()` against `(now() + timedelta(days=N)).date()`.
    Rolling datetime comparisons (`dueAt < now + N days`) shift their buckets
    with the run time — a midday run puts tomorrow-morning cards in Today.
    Never re-add fixed offsets (like the old `- timedelta(days=1)`) as
    timezone compensation: `as_datetime` returns tz-aware values and
    `as_local` handles the conversion.
